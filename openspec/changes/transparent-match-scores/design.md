## Context

The UI currently displays `match_score` as a simple numeric percentage (e.g., 85%). However, the backend (`inspect_db.py` / `data_loader.py`) also processes a `match_analysis` field that contains the reasoning behind the score. We need to extract this and present it in a user-friendly, actionable way in the frontend.

## Goals / Non-Goals

**Goals:**
- Add actionable categorical labels (Strong, Good, Low) based on the numeric `match_score` in drilldown tables.
- Display the `match_analysis` text inside the Job Details view (`insights.py` or similar).
- Provide a summary "Tip" block to teach the user how to improve their score based on the analysis text.

**Non-Goals:**
- Changing how the AI backend calculates the score or the analysis.
- Adding complex new data schemas.

## Decisions

**1. Match Score Categorization Logic:**
We will use the following standard logic to assign labels:
- `score >= 80`: "🟢 Strong Match (Ready)"
- `60 <= score < 80`: "🟡 Good Match (Tailor Resume)"
- `score < 60`: "🔴 Low Match (Major Gaps)"

These labels will be injected dynamically into the `display_rows` during `overview.py` processing for tables like "View All Jobs".

**2. Extracting Coaching Tips:**
Since `match_analysis` is currently an unstructured text block generated by the AI backend, we will surface it directly as an expandable "AI Analysis & Coaching" block in the Job Details UI. We will use a `st.info` or `st.expander` block labeled "💡 How to Improve Your Score for Upcoming Jobs" which will render the `match_analysis` and provide generic tailoring tips if the analysis is empty.

## Risks / Trade-offs

- **Risk:** Some legacy jobs might not have `match_analysis` populated.
  **Mitigation:** The UI will gracefully fallback to a generic coaching tip (e.g., "Tailor your resume by adding keywords from the job description") if the database field is null or empty.
